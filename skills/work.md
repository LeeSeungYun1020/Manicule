# 코드 구현

[공통 규칙](skills.md)을 적용한다.

## 준비

1. 전달받은 `plan/tasks/<작업>.md`를 읽고 목표·범위·구현 순서·완료 조건을 확인한다. 계획 파일이 없거나 읽을 수 없으면 사용자에게 파일 또는 접근 가능한 경로를 요구한다. 범위가 불명확하면 확정된 범위를 요구하고 구현을 보류한다. 계획 단계를 대신 수행하지 않는다. 이 파일은 세션 간 전달용이며 commit·PR에 포함하지 않는다.
2. 계획의 기준 main SHA·확정 계약·수정 대상과 현재 코드를 대조한다. 계획 이후 변경으로 구현 전제가 달라졌을 때만 해당 부분을 다시 확인한다. 선행 PR 조사를 반복하지 않는다.
3. [공통 작업 디렉터리 규칙](skills.md#작업-디렉터리)에 따라 대상 브랜치나 작업 전용 워크트리를 준비한다. 다른 세션의 로컬 브랜치를 전환하지 않는다.
4. 미해결 의존성·소유권 충돌 또는 새 의사결정이 필요한 경우에만 해당 작업을 보류한다. 확정한 계획 범위는 계속 구현한다.

## 구현과 완료

1. 빌드 가능한 commit 단위로 구현하고 [code-change.md](code-change.md)에 따라 검증·commit한다.
2. 선택한 PR 범위가 완료되면 마지막 검증이 최종 변경 상태를 포함하는지 확인한다. 변경되지 않은 입력에 대한 성공한 검증은 반복하지 않는다.
3. UI 변경이면 UI 가이드의 관련 완료 체크리스트를 점검한다.
4. 레인 상태가 바뀌면 작업 종료 시 `plan/current.md`의 해당 레인 상태와 다음 범위만 한 번 갱신하고, 문서 검증 후 해당 변경을 stage·commit한다.
5. 구현 단계의 완료 범위인 PR 생성을 [pr-create.md](pr-create.md)로 진행한다. 사용자가 로컬 수정까지만 요청했거나 게시를 보류했다면 그 범위를 따른다. 구현 결과·검증 상태·PR URL(생성한 경우)을 반환하고 종료한다. 리뷰·반영은 별도 요청을 받은 뒤 수행한다.
