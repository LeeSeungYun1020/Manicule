# 작업 - 코드 구현

## 전제 조건

- 구현할 PR 작업이 `plan/current.md`의 다음 범위 또는 사용자 지시에서 식별되어 있음.
- 현재 작업과 충돌하는 미완료 작업이 없고, 기존 작업 트리 변경을 확인해 현재 PR의 소유 범위 밖 변경을 보존할 수 있음.

## 실행 절차

- 준비 단계 -> 실행 단계로 나누어 진행.

### 준비 단계

1. `plan` 디렉토리의 계획 문서를 모두 확인. `plan.md`, `structure.md`, `order.md`, `current.md`와 작업에 관련된 `prototype` 문서를 포함.
2. 사용자 지시와 `plan/order.md`를 기준으로 리뷰 초점, 구현 범위, 제외 범위, 의존 작업과 완료 기준을 작업 계획에서 확정.
3. 의존 작업이 완료되지 않았거나 다른 작업과 변경 소유권이 겹치면 구현을 시작하지 않고 사용자에게 표시.
4. 작업 트리의 기존 변경을 확인하고 작업 전 `ai/{현재 작업}` 형태의 브랜치로 전환.
5. 코드 변경이 포함되면 작업 관련 android 가이드와 권장사항 확인.
6. 한 작업 세션에서는 하나의 PR 작업만 계획. PR의 리뷰 초점을 먼저 확정하고, 그 범위 안에서 빌드 가능한 commit 단위로 나눔.
7. 리뷰 초점, 구현 범위, 제외 범위, 의존 작업과 완료 기준을 포함해 작업 계획을 핵심 요약하여 출력. 사용자 의사결정이 필요한 내용이 있다면 번호 있는 리스트로 정리하여 함께 출력.
8. 종료 후 사용자 답변 대기.
9. 작업 계획 수정.

### 실행 단계

1. 선택한 PR 작업 범위 안에서 계획한 commit 단위로 구현.
2. 각 commit은 `code-change.md`의 세부 절차에 따라 수정·검증·기록.
3. 다음 commit 단위 구현 계속 실행. 선택한 PR 작업의 모든 단위 완료 시 최종 완료 및 검증.

## 제약 사항

- 작업 계획은 android 가이드와 kotlin 가이드를 준수해야 함.
	- android-cli 스킬 활용. android 가이드 확인 후 계획에 반영
	- kotlin Documentation(https://kotlinlang.org/docs/coding-conventions.html) 준수
- 코드, 주석, git commit message를 포함한 모든 텍스트는 간결하고 이해하기 쉽게 작성. 필요하지 않은 부차적인 내용과 미사여구 삭제.
- 각 진행 중인 단계 표시(예: `<WORK-준비-4>`, `<WORK-실행-6>`)
- 파일 수정 도구(`write_to_file`, `replace_file_content`, `multi_replace_file_content`, `Write`, `Edit` 등) 호출 전 변경 계획과 실제 코드(markdown)를 채팅 텍스트로 반드시 출력
- 각 파일마다 수정 계획과 코드 변경 사항 출력(다른 내용을 +- 형태로 알기 쉽게 표시) 후에 사용자 피드백(승인, 수정 지시)을 받아야 파일 수정 도구를 호출 가능
- 사용자의 수정 인가는 설명 받은 내용과 변경 사항에 한정되며, 다른 파일에 추가 수정이 필요한 경우 중단하고 사용자에 내용 출력.

## 예외(에러) 대응

- 계획에 따라 구현이 불가능한 경우, 중단하고 사용자에 내용 표시.
- 사용자 의사결정이 필요한 내용이 있으면, 중단하고 사용자 확인 후 계속 진행.

## 최종 완료 및 검증

1. `code-change.md`에서 변경 유형에 맞는 검증 단계 재수행.
2. android, kotlin 가이드 준수 여부 최종 점검 및 요약 보고.
3. 검증 및 점검에 문제가 있으면 종료 및 해결 방안 출력.
4. 레인 상태가 변경되었다면 `plan/current.md`에서 해당 레인의 상태와 다음 범위만 업데이트하고 commit. 메시지는 `docs: $현재_작업 구현 완료` 형태.
5. push와 PR 생성은 `pr-create.md`에서 진행.
