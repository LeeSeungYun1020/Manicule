# 구현 계획

[공통 규칙](skills.md)을 적용한다. 최신 `origin/main`을 기준으로 모든 의사결정을 확정하고 구현 세션에 전달할 `plan/tasks/<작업>.md`만 추가한다. 기존 코드·계획·current·history 등 다른 파일은 수정하지 않는다.

## 실행

1. `git fetch origin main` 후 `git rev-parse origin/main`으로 기준 SHA를 확인한다. 공통 작업 디렉터리 규칙에 따라 최신 main의 코드·문서를 읽을 디렉터리를 준비한다. 다른 작업 브랜치의 파일을 최신 main으로 간주하지 않는다.
2. 사용자 지시와 해당 기준의 `plan/current.md`에서 다음 작업을 확인한다. [선택 읽기 기준](../AGENTS.md)에 따라 관련 요구사항·구조·`plan/order.md`와 기존 코드·사용부·테스트를 확인한다.
3. 선행 PR이 main에 반영되었는지, 공용 API와 변경 소유권이 준비되었는지 계획 단계에서 확인한다. 관련 공식 가이드와 필요한 사용자 질문으로 설계·범위·검증 방법을 확정한다. 미완료 선행 작업·충돌·미결정 사항이 남아 있으면 최종 계획 전달을 보류한다.
4. 하나의 PR에 대한 계획 파일을 작성한다. 아래 구현에 필요한 결과만 포함하고, 해결된 선행 PR 목록·검토 과정·기획 원문·코드 전체는 전달하지 않는다.
   - 목표·리뷰 초점, 구현 범위와 제외 범위
   - 기준 main SHA, 변경할 파일·공용 API의 확정 계약과 소유 범위
   - 관련 요구사항의 파일·절, 수정할 코드·테스트의 위치
   - 구현 순서와 빌드 가능한 commit 단위, 필요한 설계 결정과 이유
   - 완료 조건과 변경 유형별 검증 명령
5. 미결정 사항이 없는 계획 파일의 절대 경로와 시작 시 확인한 기준 SHA를 전달하고 종료한다. 이 파일은 구현 세션에 전달하는 로컬 자료로 유지하며 commit·PR에 포함하지 않는다. 별도 워크트리의 파일도 다음 세션이 해당 경로에서 읽도록 전달한다. 구현은 진행하지 않는다.
