# a542480 — refactor: feature navigation 경계 적용

**Files**: `feature/*/navigation/*Navigation.kt`, `ManiculeNavHost.kt`, `TopLevelDestination.kt`

## 결정

- route 타입과 `NavGraphBuilder.<name>Screen()` destination을 각 feature 모듈이 함께 소유한다.
- app 모듈은 feature navigation 확장을 등록하고 최상위 이동 상태만 조립한다.

## 이유

- 버티컬 레인이 자신의 navigation 파일에서 stub을 실제 화면으로 교체할 수 있어 feature 구현과 app 조립의 변경 책임이 겹치지 않는다.
- route 인자와 destination 등록을 같은 모듈에 두면 type-safe Navigation 계약을 feature 경계에서 컴파일로 검증할 수 있다.
