# 95a80b1

## 변경 사항
- DataSource 구현체의 네이밍 규칙 변경 (`*Impl` -> `[Technology]*DataSource`)

## 의사결정 사유 (WHY)
- `*Impl`이라는 모호한 접미사 대신, 구현체가 내부적으로 사용하는 기술(`Room`, `Retrofit`, `DataStore` 등)을 클래스 이름에 명시하여 책임과 구현 방식을 명확히 드러내기 위함.
- 인터페이스는 여전히 `Remote`와 `Local` 구분을 유지하여, Entity와 DTO 간의 역할 분리 및 ISP(인터페이스 분리 원칙)를 지속 준수함.
- 외부 API 통신 구현체는 특정 API 이름(`Nlk`) 대신 범용적인 통신 기술명(`Retrofit`)을 접두사로 사용하여, 추후 다른 라이브러리(Ktor 등)로 대체되거나 추가될 경우에도 네이밍 규칙을 일관되게 유지하기 위함.
