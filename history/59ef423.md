# 59ef423 — build: ktlint multiline-expression-wrapping 규칙 비활성화

**Files**: `.editorconfig`

## 결정
- `.editorconfig`에 `ktlint_standard_multiline-expression-wrapping = disabled` 추가하여 해당 규칙 비활성화

## 이유
- Compose `Modifier` 체이닝 시, 메서드 체이닝(`...`)이 길어질 경우 `=` 다음 줄부터 시작하도록 강제하는 ktlint 0.50+의 `multiline-expression-wrapping` 규칙과, 체이닝 점 위치를 검사하는 `chain-method-continuation` 규칙이 겹치면서 `ktlintFormat`이 두 조건을 모두 만족시키지 못해 자동 포맷팅 핑퐁 버그 및 빌드 실패를 일으킴.
- Android 및 Compose 공식 가이드에서는 각 `Modifier` 메서드마다 자연스러운 줄바꿈과 1번의 탭 들여쓰기(+4 spaces)를 권장하고 있으며, 해당 린트 규칙은 이를 과도하게 제약함.
- 대안으로 체이닝 없이 `Modifier.A().then(Modifier.B())`처럼 변수를 쪼개어 연결할 수도 있으나, 이 방식은 Compose 개발 경험과 코드 가독성을 불필요하게 해치기 때문에 프로젝트 전체 단위에서 린트 규칙을 끄는 것이 이득이라고 판단함.
