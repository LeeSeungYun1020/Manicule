# 7f46d71 — feat: 독서 기록 추가와 첫 기록 상태 전환 구현

**Files**: `ReadingRecordDao.kt`, `ReadingRecordRepository.kt`, `AddReadingRecordUseCase.kt`

## 결정
- V4 기록 추가의 첫 PR은 공용 추가 계약과 원자적 저장으로 분리한다. 목록·추가 시트, 완독 확인 신호·다이얼로그는 후속 범위다.
- 새 세션 추가는 기존 upsert와 분리하고, 첫 기록 판정·WANT → READING 전환·수정 시각 갱신·insert를 하나의 Room 트랜잭션으로 처리한다.
- 미등록 책은 상태를 임의로 선택하거나 서재에 등록하지 않는다. 다른 상태와 별점·메모·완독일은 보존한다.
- UseCase는 입력을 모델로 검증하고 주입된 Clock의 수정 시각과 함께 저장하며 생성 ID를 반환한다.

## 이유
- 공용 저장 의미 변경과 입력 화면 상태 머신을 별도 검토한다. 실제 Room의 실패 롤백·동시 추가 테스트로 기반 PR을 독립 검증할 수 있다.
- Repository 두 개를 순차 호출하면 기록만 저장되거나 상태만 전환될 수 있다. 트랜잭션 내부에서 최초 여부를 판단해야 동시 추가에도 일관성을 유지한다.
- 재독과 같은 날 여러 세션은 새 ID로 보존하고, 기존 기록을 덮어쓰지 않는다.
- 서재 등록은 명시적인 상태 선택 규칙을 유지한다. 완독 확인은 저장 성공과 다른 후속 동작이므로 미구현 결과 타입을 남기지 않는다.
